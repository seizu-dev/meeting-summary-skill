# Windows サウンドレコーダーの録音ファイル

Windows 標準の「サウンド レコーダー」アプリで録音したファイルを [../SKILL.md](../SKILL.md) の手順に流し込む場合の情報。

以下は Windows 11 環境で実機確認した内容。

## ファイルの所在と命名規約

| 項目 | 内容 |
| --- | --- |
| 保存先 | ドキュメントフォルダ配下の `サウンド レコーディング`（英語環境では `Sound recordings`） |
| ファイル名 | `レコーディング.m4a`、2つ目以降は `レコーディング (2).m4a` のような連番 |
| 形式（既定） | AAC / 48kHz / 2ch / 約203kbps、MP4 コンテナの `.m4a` |
| ファイルサイズ | 約1.5MB/分（既定の 203kbps の場合） |

### 保存先の注意

**ドキュメントフォルダが OneDrive にリダイレクトされている環境では `$HOME/Documents` に無い。** 実機では以下にあった。

```
$HOME/OneDrive/ドキュメント/サウンド レコーディング/
```

パスを決め打ちせず、見つからなければ両方を探すか、ユーザーに確認すること。

### ファイル名から会議を特定できない

**ファイル名にタイムスタンプも会議名も含まれない。** `レコーディング (2).m4a` のような連番なので、複数ある場合はファイル名だけでは区別できない。

録音日時は次項の `creation_time` から取得する（[../SKILL.md](../SKILL.md) の Step 1 のスニペットがこれを行う）。

## creation_time で録音開始時刻が取れる

MP4 コンテナの `creation_time` タグに**録音開始時刻が UTC で記録されている**。

```bash
ffprobe -v error -show_entries format_tags=creation_time -of csv=p=0 "<file>.m4a"
# => 2026-09-09T03:09:10.000000Z
```

実測2件での検算（JST 環境、日付は伏せてある）:

| 項目 | 録音A | 録音B |
| --- | --- | --- |
| `duration` | 2,447.39秒（40分47秒） | 3,154.14秒（52分34秒） |
| `creation_time`（UTC） | 03:09:10 | 04:39:19 |
| 開始（JST 換算） | 12:09:10 | 13:39:19 |
| 開始 + `duration` | 12:49:57 | 14:31:53 |
| mtime（実測） | 12:49:56 | 14:31:54 |
| 差 | 1.4秒 | 0.9秒 |

**`creation_time` = 録音開始時刻、mtime = 録音終了時刻**として扱ってよい精度がある。OneDrive 同期などで mtime が変わるおそれがある環境でも、`creation_time` はファイル内のメタデータなので影響を受けない。

## 音声の欠落は無い

実音声の長さ（パケットの `duration_time` の総和）とタイムライン長（`format=duration`）の差は、40分・52分の録音でいずれも **0.05秒未満（0.00%）** だった。

tl;dv で観測されたような周期的な取りこぼし（[tldv.md](tldv.md) 参照）は**このソースでは起きない**。録音長をユーザーに伝えるとき、どちらの値を使っても差は出ない。

## 録音内容についての注意

**サウンドレコーダーは、録音デバイスとして選択された入力の音声のみを記録する。** 既定ではマイク入力になるため、オンライン会議で相手の声も録りたい場合は、ループバック（ステレオミキサー）デバイスを録音デバイスに選ぶか、会議ツール側の録音機能を使う必要がある。

※この点は仕様上の説明であり、**本スキルの検証では実機確認していない**。対面の会議やスピーカー再生を含めたマイク録音では問題にならない。

## 変換について

既定の AAC 203kbps / 2ch から [../SKILL.md](../SKILL.md) の Step 3 の設定（モノラル / 16kHz / 64kbps mp3）へ変換すると、ファイルサイズはおおよそ 1/3 になる。変換コマンド自体は他のソースと同じでよい。
